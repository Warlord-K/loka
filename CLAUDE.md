# Loka - agent guide

Loka runs persistent coding agents for one person on one Mac. Each agent lives in a pixel world, keeps one long-lived **main session** (a real Claude, Codex, Cursor, omp or OpenCode CLI session), and **forks** it into a task session for every quest. The task session works in its own worktree, can get an independent review, and the runtime commits, pushes, opens the PR and reports back into the main session.

User-facing copy says **Loka**; code, routes, ids, JSON fields and localStorage keys say `world`. The home region is `Hearth` in code and **Home** on screen. The code is the source of truth: this file lists where things live and the invariants that cause bugs when missed. Read the linked file before changing a subsystem.

## House rules

- No code comments of any kind. Functional strings (prompts, SQL, log messages) are fine.
- No em dashes in text people or agents see. `prompts::plain_dashes` also strips them from agent replies.
- No `Co-Authored-By` trailers. Stage files by exact path.
- Never edit a shipped migration; the API rejects changed checksums. Add the next free number in `migrations/`.
- UI: `w-*` colour tokens from `frontend/app/globals.css`, Tailwind only, building blocks from `styles.ts`, `motion.ts` and `controls.tsx`. Size in rem, never `[..px]` except borders, shadows and pixel art (the root font grows from 1440 px wide). Live state is `Shimmer` text, never pulsing dots. Respect `prefers-reduced-motion`.
- A new feature or a bug fix people would notice adds a line to the newest entry in [frontend/lib/changelog.ts](frontend/lib/changelog.ts) (new dated entry when the day changes). Never log UI restyling (spacing, colours, icons, buttons, loading or empty states, animations, layout): at most one line such as "Smaller UI fixes and polish" per entry. Never log internals people cannot see (prompt changes, new agent tools or parameters, refactors, performance without a felt effect, tests, build); when an internal change creates a behaviour people notice, describe the behaviour.
- UI that only makes sense with other people (shared keys, sharing toggles) sits behind `!SOLO &&` from [frontend/lib/edition.ts](frontend/lib/edition.ts), which is `true` here; keep those guards when you edit the code around them.
- Keep this file short: one line per subsystem, invariants only.

## Layout

```
shared/    loka-shared: all SQL and domain logic (WorldStore in shared/src/world.rs)
api/       loka-api (Axum): REST, SSE, runner API, external MCP, webhooks; applies migrations on start
agent/     loka-agent: `runner` (drives the CLIs), `mcp` (World tools), `world` (optional worker)
frontend/  Next.js 16 app: the world, chat, quests, reports, settings
desktop/   Tauri app: bundles Postgres, the API, the web app and the runner; workbench, terminal, Slack capture
migrations/ numbered SQL
```

The app runs everything on `127.0.0.1` with `AUTH_DISABLED=true`, so every request is the one local user. `auth::LocalPolicy` refuses requests whose `Host` is not local or whose `Origin` is not an exact app origin (CORS uses the same list, extend with `AUTH_DISABLED_ORIGINS`), and every owner request also needs the per-launch app session: the desktop writes `app-session.key` (0600), passes `LOKA_APP_SESSION_FILE` to the API, sends `x-loka-app-session` on its own calls and opens the window through a one-time `/api/app-session?code=` link that sets the HttpOnly SameSite=Strict `loka-app-session` cookie (`loka-api login-link` in development). Sandboxes deny `local.json` and `app-session.key`. Its data lives in `~/Library/Application Support/dev.ygpt.loka` ([desktop/src-tauri/src/local.rs](desktop/src-tauri/src/local.rs)).

## Runtime invariants

- **Nothing polls.** Inserts fire `pg_notify` on `agent_inbox`, `session_runs` (queued), `schedules` and `world_events`; listeners wake. A 60 s sweep only reclaims stale claims and runs the merge watch. New wakeups go through these channels.
- **Inbox** ([agent/src/world/turn.rs](agent/src/world/turn.rs)): per agent and serial, up to 20 items per main turn. Every item is stamped in SQL with whether the owner sent it; only owner messages unlock actions on the owner's setup.
- **Main turns are lean**: no shell or file tools (read-only skill files at most), only the `world` MCP tools. The turn ends with an `<!-- actions [...] actions -->` block (`reply`, `start_task`, `ask`, ...).
- **Task runs** ([agent/src/world/runs.rs](agent/src/world/runs.rs)): claimed `SKIP LOCKED`, heartbeat 30 s, time limit per quest. Never two runs on one CLI session; `start_task` reuses an existing task session. Tasks end with a `report` block, reviewers with a `verdict` block (parsers in `prompts.rs`).
- **Failures explain themselves** ([shared/src/run_causes.rs](shared/src/run_causes.rs), [shared/src/cli_errors.rs](shared/src/cli_errors.rs)): every bad run gets a `cause` and a plain diagnosis; transient errors retry once, missing reports are nudged then synthesized.
- **Closed state is sticky**: `finish_run` only closes queued or running runs; cancelled quests and archived sessions never come back.
- **Publish is idempotent**: nothing ahead of base means no `gh` call; open PRs are reused. `workspace::branch_publish_choice` (pure `publish_choice`) runs first against a freshly fetched base: a branch with nothing of its own, or unrelated to the base but with trees the base already has, finishes without a PR; an unrelated branch with real commits fails with `run_causes::unrelated_history_error`. Leftover uncommitted work is committed only signed (`workspace::commit_signed`), never unsigned. With `WORLD_API_COMMITS` on (default) publish creates each commit through GitHub's `createCommitOnBranch` ([agent/src/git/api_commits.rs](agent/src/git/api_commits.rs)) so GitHub signs it, and falls back to a signed `git push` for merges, executables, symlinks, submodules or large changes. A HEAD that extends an open PR of the owner updates that PR instead of opening a duplicate.
- **Merging from a quest worktree**: `gh pr merge --delete-branch` fails there (gh checks out the base, which the shared repo worktree holds), so quest templates merge with `gh pr merge N --squash --match-head-commit <sha>` and delete the branch with `gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>` (404 or 422 = already gone). A merge-only follow-up queues no review.
- **Quest context** ([shared/src/context.rs](shared/src/context.rs) `QuestContext`, `fork_choice`, `fresh_retry`, migration 138): `agent_profiles.quest_context` (`lean` default, `auto`, `full`) plus a per-quest `agent_tasks.context` override. Lean starts are fresh (baseline `{}`, `fresh_start_memory`: persona, notes, repo notes, rules, recent quests, never the main chat); `auto` forks until the inherited context passes half the window; `full` forks but is capped by `fork_limit` (70% of the window), past which the quest starts fresh too. A fork that fails its first turn with `context_too_long` is retried once fresh.
- **Quest options** ([shared/src/quests.rs](shared/src/quests.rs)): plan first, best of N, CI feedback, pace, time limits. All off by default; sessions open only through `quests::open_sessions`.
- **Instruction changes** are hashed into `agent_sessions.rules_hash` and announced in the next turn; never put changing content only in the system prompt.
- **Compaction** runs after a main turn passes `WORLD_COMPACT_TOKENS`, with a floor so oversized prompts do not compact every turn.
- **Costs**: CLI totals are cumulative per session across resumes, warm processes and forks, so runs store deltas against `agent_sessions.usage_baseline`. A fork takes the parent's baseline when it first runs (`WorldStore::take_fork_baseline`), a Claude total below the baseline (a killed process loses its `cost-state` line) is priced from that run's own tokens, and failed or stopped Codex runs fold their tokens into the baseline by trigger (migration 136). Dollars are list prices. All spend goes through `session_runs` so the totals and budget triggers see it. Token-only CLIs are priced by [shared/src/pricing.rs](shared/src/pricing.rs).
- **Pausing**: every claim path skips paused agents. Budget pauses stop running work and lift the next UTC day.

## Backends

Each CLI's fork, resume, rewind, steering, warm process and MCP setup are compared in [docs/backends.md](docs/backends.md). ## Runner

[agent/src/remote_runner.rs](agent/src/remote_runner.rs), server side in [shared/src/runners.rs](shared/src/runners.rs) and [api/src/routes/runners.rs](api/src/routes/runners.rs). One runner per person. It never gets database credentials: each loop is one `POST /api/runner/{id}/poll`, woken by a `/stream`. `has_work` must mirror the claim filters or wakes loop. Chat and work run in separate lanes. Every runner Unix socket goes through `cli::socket_path`: macOS caps socket paths at 104 bytes, so a long root moves the socket to `$TMPDIR/loka-<hash>/`. A sleeping Mac keeps its lease and resumes the run on wake. Git and gh on a workspace go through `cli::workspace_command`, which disables repo hooks, filters and helpers.

## Safety

- **Owner work fails closed**: `sandbox::mode()` keeps the default `auto` sandbox on for owner quests (`WORLD_TASK_SANDBOX=off` is the only way out), and an Auto approval that the CLI cannot honour refuses to start (`AUTO_UNAVAILABLE_FIX`) instead of falling back to bypass; only Full approval bypasses. Claude auto mode also gets `OWN_BRANCH_FORCE_PUSH` plus the owner's approved actions. `~/.ssh` is hidden except `config`, `known_hosts`, the agent socket, the karna/loka signing keys and the `.pub` of the configured signing key. Lean turns stay tool-less.
- **Sandbox** ([agent/src/claude/sandbox.rs](agent/src/claude/sandbox.rs), [agent/src/sandbox_wrap.rs](agent/src/sandbox_wrap.rs)): credential paths hidden, writes limited to the worktree, its git dir, temp and caches. CLI env is an allowlist (`cli::configure_child_environment`) plus the agent's granted keys; host secrets are redacted from output. Each quest gets its own temp dir (`cli::quest_temp_dir`, prefix `loka-q-`, writable in the sandbox), deleted an hour after the quest closes; runs refuse to start under 5 GB free. Quest commits are signed only with the configured key or Loka's own `~/.ssh/loka_signing` (`workspace::sign_with_loka_key`, created when neither exists), never another key; readiness `signing` reports it and the main agent tells the owner once (`tell_signing_problem`).
- **Powers** ([shared/src/powers.rs](shared/src/powers.rs)) are stored as revocations, so new powers default on. Owner-setup tools need `owner_asked_now`.
- **Keys** ([shared/src/environment.rs](shared/src/environment.rs)): encrypted, granted per agent, masked `***` everywhere, resolved only through `${secret:KEY}`. The MCP hub ([agent/src/mcp_hub/](agent/src/mcp_hub/)) keeps resolved values out of files and arguments. A kit server with an unreadable definition or ungranted keys is skipped with a warning, never failing the run (`environment::runnable_definition`, `missing_secrets`); `mcp-remote` sign-ins live in `mcp-auth/<owner>` (`mcp_hub::pin_sign_in_dirs`), never in a worktree. `mcp-remote` logins live in `{root}/mcp-auth`, private to the runner (`cli::MCP_AUTH_DIR`), and `.mcp-auth` or `***` folders are never committed or diffed (`NEVER_COMMITTED` in workspace.rs).
- **Non-owner input** (feeds, Slack, webhooks, other people) is marked `[not your owner]` and handled in tool-less asides ([shared/src/guests.rs](shared/src/guests.rs)).
- **Agent browser** ([agent/src/browser.rs](agent/src/browser.rs)) runs only through the runner's gated `browser` subcommand, which trusts `WORLD_GATE_ROOT`/`WORLD_RUNNER_ROOT` only when it canonicalizes to a real, user-owned `runner` dir of the Loka app folder (or its `servers/<key>/runner`) under the real home.
- **Desktop commands** check origin and owner; every new Tauri command must be listed in `build.rs` and `capabilities/main.json`.

## Running and testing

Development setup is in [CONTRIBUTING.md](CONTRIBUTING.md). Before a PR:

```bash
cargo clippy --workspace --all-targets
cargo test --workspace
cd frontend && npm run build
```

Database tests skip themselves unless their variable (`STEER_TEST_DATABASE_URL`, `QUESTS_TEST_DATABASE_URL`, `TEAMS_TEST_DATABASE_URL`, ...) points at a migrated database; `git grep TEST_DATABASE_URL` lists them. Tests sharing a database create their own users and agents and use per-run tokens. Live CLI checks are `#[ignore]` tests (`parity_live`, `live_backend_bench`, `live_sandboxed_task`); run them one at a time. Slack scripts: `/usr/bin/python3 -m pytest desktop/tests`.
